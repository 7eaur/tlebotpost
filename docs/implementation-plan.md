# Implementation Plan

## Phase 0 — Foundation (الحالية)

- [x] حفظ النظام القديم في `legacy/smart-poster`.
- [x] تنظيف `main` من النظام القديم.
- [x] تثبيت هدف المشروع وقرارات live-only.
- [x] اعتماد SQLite الخفيفة وعدم تخزين محتوى المنشورات.
- [x] اعتماد البوت كواجهة الإدارة.
- [x] اعتماد تنظيف الحقوق والروابط والرموز التعبيرية.
- [ ] مراجعة هذه الوثائق واعتمادها.

## Phase 1 — Skeleton — مكتملة

- [x] إنشاء `backend/app` مع نقاط دخول واضحة.
- [x] إعداد `pyproject.toml` و`.env.example` و`.gitignore`.
- [x] إعداد logging آمن.
- [x] إضافة اختبارات إعدادات وSQLite أولية.

**نقطة التحقق:** نجح تشغيل التطبيق في وضع config-check وتهيئة SQLite دون اتصال Telegram، مع نجاح الاختبارات وRuff.

## Phase 2 — SQLite Repositories — مكتملة

- [x] بناء الجداول الثلاثة: `sources`, `settings`, `event_log`.
- [x] إضافة repositories صغيرة للمصادر والإعدادات والمؤشر.
- [x] اختبار baseline عند الإضافة وإعادة التشغيل.
- [x] إضافة تنظيف دوري لـ `event_log`.

**نقطة التحقق:** نجحت 7 اختبارات وRuff، ولا يتم حفظ `message_text` أو `media` في قاعدة البيانات.

## Phase 3 — Telegram Session & Listener

- تشغيل جلسة المستخدم وتسجيل الدخول.
- إضافة/حل القنوات العامة والخاصة.
- التقاط `NewMessage` فقط.
- اعتماد baseline عند startup/reconnect.
- تجميع الألبومات.

**نقطة التحقق:** رسائل ما قبل baseline لا تصل إلى Publisher.

## Phase 4 — Transformer & Publisher

- إزالة الروابط وحقوق المصادر.
- إزالة الرموز التعبيرية.
- إضافة footer/link ثابت خاص بنا.
- إرسال الرسالة كرسالة جديدة.
- دعم النص والوسائط والألبومات.
- معالجة FloodWait وإعادة الاتصال.

**نقطة التحقق:** اختبار يدوي في قناة تجريبية واحدة.

## Phase 5 — Control Bot

- `/start`, `/help`, `/status`.
- `/addsource`, `/removesource`, `/sources`.
- `/settarget`, `/target`.
- تفعيل/تعطيل المصدر.
- pause/resume.
- إعداد الفلاتر من الأزرار أو الأوامر.
- قبول تسجيل الدخول من البوت بطريقة آمنة.

**نقطة التحقق:** مستخدم غير `OWNER_ID` لا يستطيع تغيير أي إعداد.

## Phase 6 — Tests & Operations

- اختبارات وحدات للتحويل والفلاتر والألبومات والمؤشر.
- Dockerfile وCompose.
- Volume للبيانات والجلسة.
- healthcheck و`restart: unless-stopped`.
- دليل تشغيل الخادم.
- تشغيل lint/type checks واختبارات كاملة.

## Phase 7 — Pilot

- مصدر تجريبي واحد.
- هدف تجريبي واحد.
- اختبار نص، صورة، فيديو، وألبوم.
- اختبار توقف/تشغيل وإعادة تشغيل.
- التأكد من تجاهل الرسائل القديمة بعد الانقطاع.
- بعدها إضافة المصادر الفعلية.

## قواعد التنفيذ

- لا نكتب منطق Telegram قبل إنهاء Phase 0 واعتماد الوثائق.
- لا نخلط وظائف النظام القديم مع relay الجديد.
- كل وحدة مسؤولة عن شيء واحد.
- لا نحفظ محتوى المنشورات.
- كل مرحلة تنتهي باختبار واضح قبل الانتقال للتي بعدها.
