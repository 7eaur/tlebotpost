# Architecture — Telegram Channel Relay

## 1. الهدف

مراقبة عدة قنوات Telegram عبر جلسة حساب مستخدم للقراءة، وعند وصول منشور جديد يتم تنظيفه ونشره كرسالة جديدة في قناة الهدف عبر Bot API. النظام لا يستورد التاريخ القديم ولا يخزن نصوص المنشورات أو ملفاتها.

## 2. حدود النسخة الأولى

### داخل النطاق

- جلسة مستخدم Telegram عبر Telethon.
- قنوات عامة وخاصة يكون الحساب عضوًا فيها.
- قناة هدف واحدة.
- Listener لحظي للأحداث الجديدة.
- نص، صور، فيديو، ملفات، صوتيات، وألبومات.
- بوت تحكم مقيد بالمالك.
- فلترة النص وتنظيف الروابط وحقوق المصدر وإزالة الرموز التعبيرية.
- SQLite خفيفة.
- Docker وتشغيل دائم.
- تسجيل أحداث مختصر دون محتوى الرسائل.

### خارج النطاق حاليًا

- واجهة ويب مستقلة.
- تخزين أرشيف المنشورات.
- إعادة نشر التاريخ القديم.
- تعدد قنوات الأهداف.
- إعادة صياغة بالذكاء الاصطناعي.
- جدولة النشر؛ الأصل لحظي.

## 3. مبدأ الرسائل الجديدة فقط

عند إضافة مصدر أو بدء النظام أو عودة الاتصال بعد توقف:

1. يقرأ النظام أحدث `message_id` حالي في المصدر.
2. يحفظه كمؤشر بداية.
3. يتجاهل كل ما قبله.
4. ينتظر الأحداث التي تصل بعد ذلك.

أثناء التشغيل، بعد نجاح معالجة الرسالة، يتم تحديث مؤشر المصدر إلى `message_id` الأخير. لا توجد عملية catch-up للرسائل التي وصلت أثناء التوقف؛ عند العودة يبدأ النظام من الوقت الحالي كما طلب المستخدم.

هذا يجعل النظام **live-only** ويمنع استيراد آلاف الرسائل القديمة بعد إعادة التشغيل.

## 4. قاعدة البيانات

SQLite بسيطة، دون حفظ نص أو media أو نسخة من المنشور.

### `sources`

- `id`
- `chat_id` — معرف Telegram.
- `input_ref` — المعرف الذي أدخله المالك.
- `title`
- `username`
- `enabled`
- `baseline_message_id` — آخر مؤشر قراءة/نقطة بداية.
- `created_at`
- `updated_at`

### `settings`

صف واحد لإعدادات النظام:

- `target_ref`
- `target_chat_id`
- `brand_footer`
- `brand_link`
- `enabled`
- `include_keywords` بصيغة JSON بسيطة.
- `exclude_keywords` بصيغة JSON بسيطة.
- `allowed_media_types` بصيغة JSON بسيطة.
- `updated_at`

### `event_log`

سجل تشغيلي صغير بلا محتوى المنشورات:

- `id`
- `source_chat_id`
- `source_message_id`
- `event_type`
- `status`
- `error_code`
- `created_at`

سيكون السجل محدودًا/قابلًا للتنظيف حتى لا ينمو بلا نهاية. لا يتم حفظ `message_text` أو media.

## 5. تدفق التشغيل

```text
User Telegram Session
        │
        ▼
Source Listener
        │
        ├── source enabled?
        ├── message newer than baseline?
        ├── album aggregation
        ├── text/media filters
        ├── remove rights and URLs
        ├── remove emoji
        └── append fixed brand footer/link
                │
                ▼
Temporary media transfer
                │
                ▼
Bot API Publisher → Target Channel
                │
                ├── update source cursor
                └── write small operational log

Control Bot ───────► Configuration / Status / Pause / Resume
```

## 6. وحدات الكود

```text
backend/
├── app/
│   ├── config.py              # إعدادات البيئة والتحقق منها
│   ├── database.py            # SQLite والمخطط والهجرات البسيطة
│   ├── models.py              # نماذج Typed للبيانات
│   ├── telegram/
│   │   ├── session.py         # جلسة الحساب وتسجيل الدخول والاتصال
│   │   └── listener.py         # أحداث الرسائل الجديدة وbaseline
│   ├── relay/
│   │   ├── transformer.py      # الروابط والحقوق والرموز التعبيرية والتوقيع
│   │   ├── albums.py           # تجميع الألبومات
│   │   └── publisher.py        # إرسال النص والوسائط إلى الهدف
│   ├── control/
│   │   ├── bot.py              # واجهة المالك والأوامر والأزرار
│   │   ├── resolver.py          # حل القنوات العامة والخاصة
│   │   └── runtime.py           # تشغيل وإيقاف الجلسة والـ Listener
│   └── main.py                # تركيب الخدمات والإغلاق الآمن
├── tests/
├── Dockerfile
├── docker-compose.yml
└── pyproject.toml
```

كل وحدة تملك مسؤولية واحدة. لا توجد خوارزميات تدوير أو نشر دوري لأنها لا تخدم هدف الترحيل اللحظي.

## 7. قواعد التنظيف

- إزالة روابط `http://`, `https://`, `www.`، وروابط Telegram الظاهرة.
- إزالة أسطر الحقوق/المصدر التي تحتوي على مؤشرات مثل: `حقوق`, `المصدر`, `source`, `credit` إذا كانت سطرًا ختاميًا.
- عدم حذف كل علامات `@` تلقائيًا لأنها قد تكون جزءًا من المحتوى؛ سيتم حذفها فقط ضمن قواعد الحقوق أو الروابط.
- إزالة الرموز التعبيرية من نطاقات Unicode المعروفة مع الحفاظ على النص العربي والأرقام وعلامات الترقيم.
- إضافة توقيعنا الثابت في نهاية النص بعد التنظيف.
- إذا لم يبق نص مع الوسائط، ينشر الوسيط مع توقيعنا كـ caption.

## 8. الألبومات

يتم تجميع الرسائل ذات `grouped_id` خلال نافذة قصيرة قبل النشر. يرسل Publisher قائمة الوسائط كألبوم واحد مع caption واحد، ولا يرسل كل عنصر كمنشور منفصل.

## 9. التعامل مع الأخطاء

- `FloodWait`: احترام مدة الانتظار وإعادة المحاولة دون إسقاط الخدمة.
- انقطاع الشبكة: إعادة اتصال بتأخير متدرج.
- فشل مصدر واحد: تسجيل الحدث والاستمرار في مراقبة المصادر الأخرى.
- صلاحية غير كافية: إبلاغ المالك عبر بوت التحكم وتعطيل المصدر/الهدف المتأثر حسب الحالة.
- لا تتم إعادة إرسال الرسائل القديمة بعد عودة الاتصال.

## 10. الأمان

- `API_ID`, `API_HASH`, `BOT_TOKEN`, `OWNER_ID` وبيانات الجلسة خارج Git.
- جلسة الحساب ملف محلي بصلاحيات 600 داخل Volume خاص، ولا تدخل Git.
- جميع أوامر بوت التحكم تتحقق من `OWNER_ID`.
- لا يتم تسجيل نص الرسائل أو روابطها في logs.
- مجلد SQLite والجلسة Volume دائم على الخادم.
